# 테스트 규칙

## seam — 이미 정해져 있다. 작업자에게 묻지 않는다

- 기본: `app/api/*/route.ts` 핸들러를 직접 호출한다 (HTTP 서버를 띄우지 않는다)
- 예외: `lib/`의 입출력 없는 순수 함수
- 금지: 페이지 컴포넌트 렌더 테스트, 브라우저 e2e, `lib/db.ts` 내부

## 외부 프로세스

`claude -p` 등 LLM 호출은 고정 응답으로 대체한다.
검증 대상은 "LLM이 무엇을 답하는가"가 아니라 "그렇게 답했을 때 시스템이 어떻게 처리하는가"다.

## DB

모킹하지 않는다. 임시 SQLite 파일을 쓰고 테스트마다 격리한다.

## 이름과 기대값

- test name에 출처를 표기한다: `US-9: ...`, `ID-worst-wins: ...`
- **기대값은 spec 문장에서 가져온다. 코드를 실행한 결과를 보고 채우지 않는다.**

## 금지 패턴

- 단언 없는 테스트
- 응답 `status`만 확인하고 내용을 보지 않는 테스트
- `try`/`catch`로 에러를 삼키는 테스트
