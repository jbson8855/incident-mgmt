# ADR-0001 — 구현 범위

품질관리자는 장애 발생 시 계열사별 엑셀 산정표를 열어 항목을 체크해야 하는데, 장애가 자주 발생하지 않아 막상 그 순간에는 표가 낯설어 판단이 늦어진다. 이 도구는 화면에서 항목을 선택하면 점수를 자동 합산해 장애등급(1등급/2등급/3등급/등급외)을 즉시 판정하고, 그 결과와 과거 수기 이력을 조회할 수 있게 한다.

## 커버리지

| 업무 단계 | 커버 | 남는 사람 몫 |
|---|---|---|
| 기준표 최신화 (시스템별 반영률, 가중치, 등급 판정 구간을 최신 상태로 유지) | 시스템 | 값 자체(반영률이 얼마여야 하는지)를 판단하는 것은 사람 몫 |
| 장애 통지 (어느 계열사·시스템에서 장애가 났는지 파악) | 없음 | 담당자가 품질관리자에게 통지하는 절차는 도구 밖 |
| 항목 판단·입력 (비즈니스영향도/장애복잡도/고객서비스영향도 체크) | 시스템 | 어떤 시스템이 영향받았는지, 항목이 있음/없음인지 판단하는 것은 사람 몫 |
| 판단 애매 시 상급자 협의 | 없음 | 담당자 팀장과의 협의 자체는 도구 밖 |
| 미확인 항목 처리 (등급이 높게 나오는 쪽 우선) | 시스템 | "미확인"으로 둘지 결정하는 것은 사람 몫 |
| 등급 산정 (점수 합산·등급 판정) | 시스템 | — |
| 산정 결과 이력 조회 (장애등급 판정 이력) | 시스템 | — |
| 과거 장애 이력 조회 (엑셀 이관분) | 시스템 | — |
| 장애보고서 작성 및 최종 등급 재산정 | 없음 (범위 밖) | 3등급 이상 건에 대한 별도 절차 |
| 등급 전파 (조직원 통보, SMS/메신저 등) | 없음 (범위 밖) | 다음 프로젝트에서 다룸 |

## 해석에 영향을 주는 제외

- **비즈니스영향도/장애복잡도/고객서비스영향도 3축 고정** — 이 3가지 배점 축은 추가·삭제할 수 없는 고정 구조다. 총점은 항상 이 3축을 전제로 해석해야 한다.
- **기준표 값 변경의 소급 미반영** — 과거 이력은 산정 당시 시스템명·값을 스냅샷으로 저장하므로, 이후 기준표(반영률, 가중치)를 바꾸거나 시스템을 비활성화해도 이미 남은 이력의 점수·등급은 바뀌지 않는다. 현재 기준표와 과거 이력의 값이 서로 달라 보일 수 있다.
- **최초 산정만 다룸 (재산정 없음)** — 이 도구가 보여주는 등급은 항상 "최초 신속 산정" 값이다. 장애보고서 작성 시 재산정되는 최종 등급과 다를 수 있으며, 이 도구는 그 차이를 반영하지 않는다.
- **산정 결과 수정 불가** — 한 번 산정된 결과는 고칠 수 없다. 정정이 필요하면 새로 계산해 새 이력 건을 남기므로, 같은 장애에 대해 이력이 여러 건 남을 수 있다.
- **원본 시간 표기 비표준화 (과거 장애 이력)** — 발생일 외의 발생시간/조치시간/소요시간/장애보고서 필드는 엑셀 원본 표기(예: "09-01(금)")를 정정 없이 그대로 저장한다. 건마다 표기 형식이 다를 수 있다.

## 검증되지 않는 것

- **화면 표시·화면 간 이동** — 테스트 seam이 API route라 자동 검증되지 않는다.
  서버가 무엇을 내려주는지는 테스트가 잠그지만, 그것을 화면에 어떻게 그리는지는 사람이 열어 확인한다.
