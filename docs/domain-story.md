# 장애등급 산정

## 상황

계열사 시스템에서 장애가 발생했을 때, 품질관리자가 최대한 신속하게 최초 장애등급을 산정하는 상황. (장애등급을 조직원에게 전파하는 것은 이번 범위에 포함하지 않음)

## 등장인물

- **품질관리자** — 장애 발생을 통지받아 장애등급 산정표를 채우고 등급을 산정하는 주체
- **장애 시스템 담당자** — 장애가 발생한 계열사/시스템을 품질관리자에게 통지하고, 장애조치를 하면서 품질관리자와 함께 산정표 항목을 채움
- **담당자 팀장(상급자)** — 항목 판단이 애매할 때 협의 대상

## 오가는 것

- **장애 통지** — 담당자가 알려주는 "어느 계열사, 어느 시스템"에서 장애가 발생했는지에 대한 정보
- **장애등급 산정표** — 계열사별로 만들어진 엑셀. 비즈니스영향도(50%), 장애복잡도(20%: 단순장애 20%/복잡장애 80%), 고객서비스영향도(30%: 접속장애여부 30%, 응답속도 20%, 동일장애재발 50%) 항목에 체크하면 점수가 자동 합산됨
- **산정된 장애등급** — 합산 점수에 따라 판정되는 결과값 (1등급/2등급/3등급/등급외)
- **장애보고서** — 3등급 이상인 경우 작성하는 문서. 최종 장애등급을 재산정하여 기록 (이번 스토리 범위 밖의 후속 절차)

## 흐름

1. 장애 시스템 담당자가 장애 발생 시 어느 계열사, 어느 시스템에서 장애가 났는지 품질관리자에게 통지한다.
2. 품질관리자와 담당자가 함께 해당 계열사의 장애등급 산정표에서 비즈니스영향도, 장애복잡도, 고객서비스영향도 항목을 하나씩 채운다.
3. 항목 판단이 애매한 경우, 담당자의 팀장(상급자)과 협의한다.
4. 확인이 안 된 항목은 신속한 판단을 위해 등급이 높게 나오는 쪽으로 우선 선택한다.
5. 항목이 채워지면 점수가 합산되어 장애등급(1등급/2등급/3등급/등급외)이 산정된다.

## 예외

- 항목 판단이 애매한 경우 → 담당자의 팀장(상급자)과 협의한다.
- 아직 확인되지 않은 항목이 있는 경우 → 신속한 판단을 위해 등급이 높게 나오는 쪽을 우선 선택한다.
- 최초 산정한 등급과, 이후 장애보고서 작성 시 재산정한 최종 등급이 다를 수 있다 (예: 최초 1등급으로 산정됐던 것이 나중에 등급외로 바뀌는 경우도 있음).

## 끝나는 지점

최초 장애등급이 산정되면 이번 업무는 일단 끝난 것으로 본다. (이후 장애보고서 작성 시 등급을 재산정하여 최종 기록하는 것과, 3등급 이상인 경우 장애보고서를 작성해 별도로 관리하는 것은 별도 절차이며 이번 스토리 범위 밖이다.)

## 지금의 불편함

- 장애가 자주 발생하는 게 아니어서, 막상 장애가 발생하면 산정표(엑셀)가 익숙하지 않아 혼돈스럽다.
- 화면에 좀 더 친절한 안내가 있으면 좋겠다.

## 용어

| 용어 | 뜻 |
|---|---|
| 비즈니스 영향도 | 장애가 발생한 시스템별 영향도(가중치 50%)에, 전체 시스템 장애(100%)인지 일부 장애(10~50% 직접입력)인지를 곱해 반영하는 항목 |
| 장애 복잡도 | 단순장애(20%)인지 복잡장애(80%)인지 여부로 판단하는 가중치(20%) 항목 |
| 고객서비스 영향도 | 접속장애여부(30%), 응답속도(20%), 동일장애재발(50%)을 감안한 가중치(30%) 항목 |
| 장애등급 | 비즈니스영향도, 장애복잡도, 고객서비스영향도 점수를 합산한 값으로 판정. 1등급(0.8 초과 ~ 1.0), 2등급(0.7 초과 ~ 0.8), 3등급(0.5 초과 ~ 0.7), 등급외(그 외) |
| 등급외 | 위 등급 기준에 미달하는 경우 |
| 장애등급 산정표 | 계열사별로 시스템별 영향도를 감안해 만든 장애등급 체계산정 프레임워크 엑셀 |
| 장애보고서 | 3등급 이상인 장애에 대해 작성하는 문서로, 최종 장애등급을 재산정하여 기록함 |
