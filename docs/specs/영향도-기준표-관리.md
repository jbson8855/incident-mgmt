## Problem Statement

장애등급을 계산하려면 계열사별로 "어떤 시스템이 얼마나 중요한지(비즈니스영향도)", "장애복잡도 판단 기준", "고객서비스영향도 세부 가중치" 값이 미리 정해져 있어야 한다. 이 값들은 조직·시스템 변화에 따라 바뀔 수 있는데, 지금처럼 코드나 별도 엑셀 파일에만 있으면 값이 바뀔 때마다 개발자를 거치거나 파일을 따로 관리해야 해서 번거롭고 최신 상태를 보장하기 어렵다.

## Solution

품질관리자가 화면에서 직접 계열사(우선 유진기업)의 장애등급 산정 기준표 — 비즈니스영향도에 포함된 시스템별 반영률, 장애복잡도의 단순/복잡 기준값, 고객서비스영향도의 세부 항목(접속장애여부/응답속도/동일장애재발) 가중치 — 를 확인하고 수정할 수 있는 화면. 여기서 수정한 값은 곧바로 "장애등급-계산" 기능에 반영된다.

## User Stories

1. As a 품질관리자, I want 유진기업의 영향도 기준표 전체(비즈니스영향도/장애복잡도/고객서비스영향도)를 한 화면에서 보는 것, so that 지금 어떤 항목과 값으로 계산되는지 한눈에 파악할 수 있다.
2. As a 품질관리자, I want 비즈니스영향도에 속한 시스템들을 그룹(ERP, 유관시스템, 영업관리, 콘라이브, 기타 등)별로 묶어서 보는 것, so that 시스템 수가 많아도 헷갈리지 않고 찾을 수 있다.
3. As a 품질관리자, I want 특정 시스템의 반영률 값을 수정, so that 그 시스템의 중요도가 바뀌었을 때 최신 값으로 계산되게 한다.
4. As a 품질관리자, I want 새로운 시스템을 비즈니스영향도 목록에 추가, so that 신규로 도입된 시스템도 장애 발생시 선택할 수 있다.
5. As a 품질관리자, I want 더 이상 쓰지 않는 시스템을 목록에서 제외, so that 산정표가 실제 운영 중인 시스템만 담고 있도록 유지한다.
6. As a 품질관리자, I want 장애복잡도의 단순장애/복잡장애 기준값(예: 0.2 / 0.8)을 수정, so that 복잡도 판단 기준이 바뀌면 반영할 수 있다.
7. As a 품질관리자, I want 고객서비스영향도의 세 하위 항목(접속장애여부/응답속도/동일장애재발) 가중치를 각각 수정, so that 어떤 하위 항목을 더 중요하게 볼지 조정할 수 있다.
8. As a 품질관리자, I want 접속장애여부/응답속도/동일장애재발 각각의 "있음/없음" 값(예: 0.8 / 0.2)도 수정, so that 판정 기준 자체가 바뀌어도 대응할 수 있다.
9. As a 품질관리자, I want 비즈니스영향도/장애복잡도/고객서비스영향도 세 대분류의 가중치(기본 50%/20%/30%)도 필요하면 확인하고 수정, so that 전체 배점 구조 자체를 조정할 수 있다.
10. As a 품질관리자, I want 값을 수정하면 저장 버튼을 눌러 바로 반영되는 것, so that 별도 배포나 개발자 개입 없이 즉시 최신 기준으로 계산할 수 있다.
11. As a 품질관리자, I want 값이 정상 범위(0~1)를 벗어나거나 이름이 비어있을 때 저장 전에 알려주는 것, so that 잘못된 값이 들어가 계산이 틀어지는 것을 막을 수 있다.
12. As a 품질관리자, I want 세 대분류 가중치의 합이 100%에서 벗어나면 안내를 받는 것, so that 실수로 배점 구조가 깨지는 것을 미리 알아챌 수 있다.
13. As a 품질관리자, I want 시스템을 삭제해도 이미 지나간 장애 이력에는 그 시스템 이름과 당시 값이 그대로 남아있는 것, so that 과거 기록이 훼손되지 않는다.
14. As a 품질관리자, I want 총점 구간별 장애등급(1등급/2등급/3등급/등급외) 판정 기준(최소~최대)을 조회하고 수정, so that 등급 판정 기준 자체가 바뀌어도 코드 수정 없이 반영할 수 있다.

## Implementation Decisions

- 산정 기준을 4단계 계층 구조로 저장한다: **계열사 → 대분류 → 중분류 → 항목(소분류)**.
  - 계열사: 예) 유진기업. 이번 스펙에서는 유진기업 1건만 시드 데이터로 넣지만, 이후 계열사를 추가할 수 있도록 계열사 단위로 구조를 분리해둔다.
  - 대분류: 비즈니스영향도(가중치 0.5) / 장애복잡도(가중치 0.2) / 고객서비스영향도(가중치 0.3). 계열사마다 존재.
  - 중분류: 대분류에 속하며 자체 가중치를 가진다.
    - 비즈니스영향도 → "대상(업무서비스)" (가중치 1, 선택방식: 다중 선택 — 장애 시 영향받은 시스템을 중복으로 체크 가능), "서비스 장애 범위 가중치" (선택방식: 단일 선택 — 가중치 개념이 아니라 대상업무서비스 소계에 곱해지는 배율로 취급. **이 화면(영향도 기준표 관리)에는 노출하지 않고, "장애등급-계산" 화면에서만 매 건 선택·입력한다** — 자세한 내용은 그 스펙 참고)
    - 장애복잡도 → "장애심각도" (가중치 0.2, 선택방식: 단일 선택)
    - 고객서비스영향도 → "접속장애여부"(가중치 0.3), "응답속도"(가중치 0.2), "동일장애재발"(가중치 0.5) — 각각 선택방식: 단일 선택
  - 항목(소분류): 중분류에 속하는 실제 선택지. 각 항목은 이름, 값(반영률 또는 기준값, 0~1), 표시 순서를 가진다. 비즈니스영향도의 대상(업무서비스) 항목에는 화면 표시용 그룹명(ERP/유관시스템/EURAS/영업관리/콘라이브/기타)을 추가로 붙인다.
- 유진기업의 초기 데이터는 회사가 이미 쓰던 장애등급 산정 방안 문서의 값을 그대로 시드로 채워 넣는다.
  - 대상(업무서비스) 반영률(그룹별): ERP — HR(인사) 0.2 / BC(공통) 0.9 / CO(관리) 0.2 / FI(재무) 0.5 / MM(구매) 0.7 / PP(생산) 0.5 / SD(영업) 1 / TR(자금)-펌뱅킹 0.4. 유관시스템 — e-HR 0.2 / ez_A 0.1 / 통합구매(EUPROS) 0.7. EURAS — 생산관리 1 / 출하관리 1 / 품질관리 1 / 차량관제 0.5. 영업관리 — 수주영업 0.7 / 건자재영업(EUMAS) 0.7 / 영업모바일 0.7. 콘라이브 — 콘라이브 0.8. 기타 — EAI 0.7 / Smart Bill 등 0.2.
  - 서비스 장애 범위 가중치: 전사 1(100%, 고정) / 일부 0.1~0.5(10~50%, 직접입력 범위) — 데이터는 이 스펙에서 시드하지만 편집 화면은 "장애등급-계산"에 있다.
  - 그 외: 단순장애 0.2/복잡장애 0.8, 접속불가 有 0.8/無 0.2, 응답속도 성능불만 有 0.8/無 0.2, 동일장애재발 有 0.8/無 0.2.
- 항목 삭제는 실제 행 삭제가 아니라 비활성화 처리로 구현한다 (사용 안 함 표시). 이미 지난 장애 이력은 산정 당시 항목명·값을 자체적으로 복사해 저장하므로("장애-이력" 스펙 참고), 기준표에서 항목을 비활성화하거나 값을 바꿔도 과거 기록에는 영향이 없다.
- 등급 판정 기준(1등급/2등급/3등급/등급외)은 계열사별로 별도 테이블(대분류/중분류/항목 계층과 무관)에 저장한다. 각 등급은 최소값(초과)과 최대값(이하, 비어있으면 상한 없음)을 가지며, 화면 맨 아래에 별도 카드로 조회·수정한다.
- 화면은 대분류 3개를 섹션으로 나누고, 각 섹션 안에 중분류 → 항목을 트리 형태로 펼쳐 보여주는 하나의 관리 화면으로 구성한다. 항목 값 수정은 인라인으로, 항목 추가/비활성화는 섹션 내 버튼으로 처리한다.
- 저장 시 입력값 검증: 항목의 값은 0~1 사이 숫자만 허용, 이름은 공백 불가. 대분류 가중치 합이 1(100%)이 아니면 저장을 막지는 않되 화면에 경고 문구를 보여준다.
- API는 계열사 단위로 기준표 전체를 조회하는 조회용 엔드포인트와, 대분류/중분류 가중치 수정, 항목 추가/수정/비활성화를 처리하는 엔드포인트로 구성한다.

## Out of Scope

- 계열사 자체를 추가/삭제하는 화면 — 이번에는 유진기업 데이터만 다루며, 계열사 추가는 이후 단계에서 다룬다.
- 대분류(비즈니스영향도/장애복잡도/고객서비스영향도) 자체를 추가·삭제하는 기능 — 이 3가지 축은 고정된 구조로 취급한다.
- 값 변경 이력 추적(누가 언제 무엇을 바꿨는지 로그) 및 승인 절차.
- 값 변경이 과거 장애 이력에 소급 반영되는 것 — 과거 기록은 산정 당시 값을 그대로 유지한다.

## Further Notes

- 이 기준표는 "장애등급-계산" 기능이 읽어서 사용하는 기준 데이터이므로, 이 스펙을 먼저 구현해야 장애등급 계산 기능이 실제 값으로 동작할 수 있다.
- 항목명·용어는 도메인 스토리와 동일하게 사용한다 (비즈니스 영향도, 장애 복잡도, 고객서비스 영향도, 단순장애, 복잡장애 등).
