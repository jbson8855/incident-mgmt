## Problem Statement

그동안 실제 발생했던 장애(원인, 조치내역, 소요시간 등)는 팀에서 엑셀로 수기 관리해왔다. 특정 팀이나 계열사, 등급, 기간의 이력을 찾으려면 엑셀 파일을 직접 열어 필터링해야 하고, 여러 사람이 공유하며 보기도 불편하다. 이 이력은 "장애등급 판정 이력"(장애등급-계산 도구가 자동으로 남기는 산정 결과)과는 출처와 목적이 다른, 별개의 기록이다.

## Solution

엑셀로 관리하던 과거 장애 이력(팀명, 장애유형, 관계사, 장애내용, 조치사항, 발생요인, 장애요인, 이중화 구성 여부, 업무서비스 중단 여부, 중단규모, 장애등급, 발생/조치 시간, 소요시간, 장애보고서, 비고)을 DB로 옮겨, 목록에서 팀명·관계사·장애등급·발생일 기간으로 걸러보고, 건을 더블클릭하면 상세 내용을 확인할 수 있는 조회 전용 화면.

## User Stories

1. As a 품질관리자, I want 과거 장애 이력을 목록으로 조회하는 것, so that 엑셀 파일을 열지 않고도 지난 장애 현황을 한눈에 볼 수 있다.
2. As a 품질관리자, I want 목록에서 발생일·팀명·장애유형·관계사·장애등급·발생시간·소요시간·비고를 바로 보는 것, so that 자세히 열어보지 않아도 핵심 정보를 빠르게 파악할 수 있다.
3. As a 품질관리자, I want 팀명으로 목록을 걸러보는 것, so that 특정 팀이 처리한 장애만 모아볼 수 있다.
4. As a 품질관리자, I want 관계사로 목록을 걸러보는 것, so that 특정 계열사에서 발생한 장애만 모아볼 수 있다.
5. As a 품질관리자, I want 장애등급으로 목록을 걸러보는 것, so that 1등급·2등급·3등급처럼 특정 등급의 장애만 따로 볼 수 있다.
6. As a 품질관리자, I want "등급내"라는 옵션으로 1·2·3등급을 한 번에 묶어 필터링하는 것, so that 대다수를 차지하는 등급외(경미한 장애)를 빼고 의미 있는 등급의 장애만 빠르게 모아볼 수 있다.
7. As a 품질관리자, I want 등급외 항목만 따로 필터링하는 것, so that 등급이 매겨지지 않은 경미한 장애만 모아 검토할 수 있다.
8. As a 품질관리자, I want 발생일 기간(시작~종료)으로 목록을 걸러보는 것, so that 원하는 기간에 발생한 장애만 모아볼 수 있다.
9. As a 품질관리자, I want 화면을 처음 열었을 때 발생일 기간이 자동으로 "1년 전 ~ 오늘"로 설정돼 있는 것, so that 매번 기간을 직접 입력하지 않아도 최근 1년 이력을 바로 볼 수 있다.
10. As a 품질관리자, I want "필터 초기화"를 누르면 팀명·관계사·등급 조건은 지워지고 발생일 기간은 기본값(1년 전~오늘)으로 되돌아가는 것, so that 처음 화면을 열었을 때와 같은 상태로 쉽게 되돌아갈 수 있다.
11. As a 품질관리자, I want 목록의 행을 더블클릭하면 그 건의 상세 화면으로 이동하는 것, so that 목록을 훑어보다가 궁금한 건만 골라 자세히 확인할 수 있다.
12. As a 품질관리자, I want 목록 위에 "더블클릭하면 상세를 볼 수 있다"는 안내 문구가 있는 것, so that 처음 쓰는 사람도 상세 조회 방법을 바로 알 수 있다.
13. As a 품질관리자, I want 상세 화면에서 장애내용과 조치사항을 각각 문단으로 읽는 것, so that 당시 상황과 조치 흐름을 이해할 수 있다.
14. As a 품질관리자, I want 상세 화면에서 비고가 조치사항 바로 다음에 나오는 것, so that 조치와 관련된 추가 설명을 이어서 자연스럽게 읽을 수 있다.
15. As a 품질관리자, I want 상세 화면에서 발생요인(내부/외부)·장애요인(HW/APP/회선/DB)·이중화 구성 여부·업무서비스 중단 여부·중단규모·조치시간·장애보고서 여부까지 모두 확인하는 것, so that 엑셀에 있던 정보를 빠짐없이 참고할 수 있다.
16. As a 품질관리자, I want 상세 화면에서 "목록으로"를 클릭하거나 Esc 키를 누르면 목록 화면으로 돌아가는 것, so that 마우스로 버튼을 찾지 않고도 빠르게 목록으로 복귀할 수 있다.
17. As a 품질관리자, I want 이 화면에서 이력을 수정하거나 새로 등록할 수 없는 것, so that 원본 엑셀 기록이 실수로 훼손되지 않고 그대로 보존된다.
18. As a 품질관리자, I want 이력이 많아져도 페이지 단위로 나뉘어 보이는 것, so that 목록이 한 번에 너무 많이 로드되어 느려지지 않는다.
19. As a 품질관리자, I want 장애등급이 배지 색으로 구분되어 보이는 것, so that 심각한 장애를 목록에서 바로 구별할 수 있다.
20. As a 품질관리자, I want 기존 "장애등급 판정 이력"(계산기로 산정한 이력) 화면과 이 "과거 장애 이력" 화면이 메뉴에서 이름이 겹치지 않는 것, so that 두 화면을 혼동하지 않고 원하는 이력을 정확히 찾아갈 수 있다.

## Implementation Decisions

- 새 테이블 `incident_logs`를 신설한다. 기존 "장애등급 판정 이력"이 쓰는 `incident_records`(장애등급-계산 도구의 자동 산정 결과 스냅샷)와는 출처·목적이 달라 완전히 별개 테이블로 둔다.
- 컬럼 구성: 발생일(occurred_date), 팀명, 장애유형, 관계사(자유 텍스트 — `companies` 테이블과 연동하지 않음), 장애내용, 조치사항, 발생요인(내부/외부), 장애요인(HW/APP/회선/DB 등), 이중화 구성 여부, 업무서비스 중단 여부, 중단규모, 장애등급(기존 등급 타입 재사용: 1등급/2등급/3등급/등급외), 발생시간, 조치시간, 소요시간, 소요시간 구분, 장애보고서 여부, 비고.
- 발생일만 표준 날짜(YYYY-MM-DD)로 정규화해서 저장한다. 발생시간/조치시간/소요시간/소요시간 구분/장애보고서 필드는 원본 엑셀 표기가 일관되지 않지만(예: "09-01(금)", "11월 13일") 임의로 정정하면 의미가 왜곡될 수 있어 원본 텍스트 그대로 저장한다. 년도/분기/년월은 발생일로 파생 가능하므로 별도 컬럼으로 저장하지 않는다.
- 데이터 적재: 앱이 처음 구동될 때(`lib/db.ts`) 엑셀에 있던 과거 이력을 1회성으로 시드하며, 이미 데이터가 있으면 다시 넣지 않는다. 이 화면과 API에는 등록·수정·삭제 경로를 두지 않는다(조회 전용).
- API: `GET /api/incident-logs` — `teamName`, `companyName`(정확히 일치), `grade`, `startDate`/`endDate`(발생일 기준 범위), `page`, `pageSize` 쿼리 파라미터를 지원한다. `grade`에 `등급내`를 넘기면 1·2·3등급을 모두 포함(등급외 제외)해서 조회한다. 정렬은 발생일 내림차순. `GET /api/incident-logs/[id]` — 단건 상세, 없으면 404.
- 목록 화면: 발생일·팀명·장애유형·관계사·장애등급·발생시간·소요시간·비고 8개 컬럼만 노출한다(나머지 필드는 상세에서만 확인). 팀명·관계사 필터의 선택지는 별도 API 없이 조회된 데이터에서 뽑은 고유값을 사용한다. 장애등급 필터는 전체/등급내(1·2·3등급)/1등급/2등급/3등급/등급외 6가지를 제공한다. 발생일 기간의 기본값은 "오늘로부터 1년 전 ~ 오늘"이며, 필터 초기화 시에도 이 기본값으로 되돌아간다(빈 값이 아님). 목록 행은 더블클릭해야 상세로 이동하고(단일 클릭은 동작 없음), 목록 위에 안내 문구를 둔다.
- 상세 화면: 카드 순서는 요약(발생일/팀명/장애유형/관계사/발생시간/소요시간/소요시간 구분) → 장애 내용 → 조치 사항 → 비고 → 세부 정보(발생요인/장애요인/이중화 구성 여부/업무서비스 중단 여부/중단규모/조치시간/장애보고서)이다. "목록으로" 버튼 클릭 또는 Esc 키 입력 시 목록으로 돌아가며, Esc는 전역 keydown 리스너로 처리한다.
- 내비게이션: 기존 "장애 이력" 메뉴 항목(계산기 산정 이력, `/incident-history`)의 표시 이름을 "장애등급 판정 이력"으로 바꾸고, 이번에 추가한 "과거 장애 이력"(`/incident-logs`)과 이름이 겹치지 않도록 구분한다.

## Out of Scope

- 이력 등록·수정·삭제 기능 — 조회 전용이다.
- 관계사(자유 텍스트)를 `companies` 테이블과 매핑·연동하는 것.
- 발생시간/조치시간/소요시간 등 원본 표기를 표준 형식으로 통일하는 정제 작업.
- 통계·차트(예: 월별 장애 건수 추이), 엑셀로 다시 내보내는 기능.
- 팀명·관계사 필터용 별도 distinct-value 조회 API.

## Further Notes

- 이 이력은 "장애등급 판정 이력"(`docs/specs/장애-이력.md`, `incident_records`)과 데이터 출처·목적이 다르다: 후자는 도구가 자동 산정한 결과 스냅샷이고, 이번 기능은 실제 있었던 장애를 사람이 수기로 기록해온 대장을 그대로 옮긴 것이다. 두 화면을 같은 이름으로 두면 혼동되므로 화면명을 구분했다.
- 원본 엑셀에는 발생일과 년월 컬럼이 서로 맞지 않는 등 일부 오기로 보이는 값이 있었으나, 발생일만 표준화해 저장하고 년도/분기/년월 자체는 저장하지 않으므로 이 화면에는 영향이 없다.
