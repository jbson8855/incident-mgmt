## Problem Statement

품질관리자가 장애등급을 산정해도 그 결과를 다시 찾아볼 방법이 없으면, 나중에 장애보고서를 쓸 때 당시 어떤 근거로 그 등급이 나왔는지 기억에 의존해야 하고, 과거에 어떤 장애가 얼마나 있었는지도 파악하기 어렵다.

## Solution

"장애등급-계산"에서 산정된 결과가 자동으로 이력에 남고, 품질관리자가 이를 목록으로 훑어보거나 건별로 상세(당시 선택했던 항목과 최종 등급)를 다시 확인할 수 있는 화면.

## User Stories

1. As a 품질관리자, I want 지금까지 산정한 장애등급 이력을 목록으로 보는 것, so that 과거에 어떤 장애가 있었는지 한눈에 볼 수 있다.
2. As a 품질관리자, I want 목록에서 계열사, 등급, 산정 일시를 바로 보는 것, so that 원하는 건을 빠르게 찾을 수 있다.
3. As a 품질관리자, I want 등급이 색으로 구분되어 보이는 것, so that 심각한 장애를 목록에서 바로 구별할 수 있다.
4. As a 품질관리자, I want 목록에서 한 건을 눌러 상세 내용을 보는 것, so that 당시 어떤 시스템과 항목을 선택해서 그 등급이 나왔는지 확인할 수 있다.
5. As a 품질관리자, I want 상세 화면에서 총점과 비즈니스영향도/장애복잡도/고객서비스영향도 각각의 소계를 보는 것, so that 등급이 어떤 근거로 산출됐는지 이해할 수 있다.
6. As a 품질관리자, I want 상세 화면에서 당시 "미확인"으로 선택했던 항목이 표시되는 것, so that 나중에 실제 값을 확인해서 재산정할 때 무엇을 다시 확인해야 하는지 알 수 있다.
7. As a 품질관리자, I want 목록이 최근 산정 건부터 순서대로 보이는 것, so that 가장 최근 장애를 바로 확인할 수 있다.
8. As a 품질관리자, I want 계열사로 목록을 걸러서 보는 것, so that 특정 계열사의 장애 이력만 모아볼 수 있다.
9. As a 품질관리자, I want 등급으로 목록을 걸러서 보는 것, so that 예를 들어 1·2등급처럼 심각한 장애만 따로 모아볼 수 있다.
10. As a 품질관리자, I want 기간(날짜 범위)으로 목록을 걸러서 보는 것, so that 특정 기간에 발생한 장애만 모아볼 수 있다.
11. As a 품질관리자, I want 3등급 이상인 건이 눈에 띄게 표시되는 것, so that 장애보고서를 써야 하는 건을 놓치지 않을 수 있다.
12. As a 품질관리자, I want 이 화면에서는 이미 산정된 값을 고칠 수 없는 것, so that 최초 판단 기록이 실수로 바뀌지 않고 그대로 보존된다.
13. As a 품질관리자, I want 이력이 많아져도 여러 페이지로 나뉘어 보이는 것, so that 목록이 너무 길어지거나 느려지지 않는다.

## Implementation Decisions

- 장애등급 산정 결과를 저장하는 새 테이블(예: `incident_records`)을 만든다. 한 건은 다음을 포함한다: 계열사 이름, 산정 시각, 선택했던 시스템 목록(이름과 그 당시 값), 장애복잡도·접속장애여부·응답속도·동일장애재발 각각의 선택 결과(예/아니오/미확인 여부와 실제 적용된 값), 대분류별 소계(비즈니스영향도 점수/장애복잡도 점수/고객서비스영향도 점수), 총점, 최종 등급.
- 선택한 시스템·항목 값은 **그 당시의 값을 그대로 복사해서(스냅샷)** 저장한다. "영향도-기준표-관리"에서 이후에 값이 바뀌거나 시스템이 비활성화돼도, 이미 저장된 이력의 내용과 등급은 그대로 유지된다.
- 이 테이블에 새 행을 추가하는 것은 "장애등급-계산" 기능이 계산을 완료하는 순간 자동으로 이뤄진다. 이 화면 자체에는 새로 만들기/수정/삭제 기능을 두지 않고 조회(목록·상세)만 제공한다.
- 목록 화면: 산정 시각 최근 순으로 기본 정렬. 계열사, 등급, 기간(시작일~종료일) 조건으로 필터링할 수 있다. 건수가 많을 경우를 대비해 페이지 단위로 나눠 보여준다. 3등급 이상인 건은 목록에서 시각적으로 강조 표시한다.
- 상세 화면: 목록에서 한 건을 선택하면, 그 건의 계열사·산정 시각·선택했던 시스템 전체·각 항목의 선택 결과(미확인 여부 포함)·대분류별 소계·총점·최종 등급을 모두 보여준다.
- 조회 전용 API(목록 조회 시 필터·페이지 파라미터 지원, 상세 조회)만 두고, 수정·삭제용 API는 만들지 않는다.

## Out of Scope

- 이력 건을 수정하거나 삭제하는 기능 — 산정 기록은 그대로 보존한다.
- 장애보고서 작성 및 그에 따른 최종 등급 재산정 결과를 이 이력에 반영하는 것 — 별도 프로젝트에서 다룬다.
- 통계나 차트(예: 월별 장애 건수 추이) — 이번에는 목록·상세 조회까지만 다룬다.
- 이력을 파일(엑셀 등)로 내보내는 기능.

## Further Notes

- "장애등급-계산" 기능이 이 기록의 유일한 생성 경로다. 계산이 끝나는 즉시 한 건이 자동으로 만들어지므로, 이 스펙은 계산 기능이 먼저(또는 함께) 구현되어 있어야 실제로 채워진다.
- 이 이력은 향후 "장애보고서 작성 및 재산정" 기능(이번 범위 밖)의 참고 자료로 이어서 쓰일 수 있다.
- 화면명은 "장애 이력"에서 "장애등급 판정 이력"으로 변경했다. 엑셀로 수기 관리해온 실제 과거 장애 이력을 조회하는 별개 기능("과거-장애-이력", `docs/specs/과거-장애-이력.md`)이 같은 이름으로 추가되면서 혼동을 피하기 위함이다.
