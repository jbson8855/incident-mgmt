## Problem Statement

품질관리자는 장애가 발생하면 최대한 빠르게 장애등급을 판단해야 한다. 지금은 계열사별로 따로 만들어진 장애등급 산정표(엑셀)를 열어서 비즈니스영향도, 장애복잡도, 고객서비스영향도 항목을 하나씩 체크해야 하는데, 장애가 자주 발생하지 않다 보니 막상 장애가 나면 이 표가 익숙하지 않아 혼란스럽고 시간이 걸린다.

## Solution

품질관리자가 화면에서 계열사를 고르고, 장애가 발생한 시스템과 각 항목(비즈니스영향도 / 장애복잡도 / 고객서비스영향도)을 체크하면 자동으로 점수를 합산해서 장애등급(1등급/2등급/3등급/등급외)을 즉시 판정해주는 도구. 판단이 애매하거나 아직 확인이 안 된 항목은 "미확인"으로 표시해 등급이 높게 나오는 쪽으로 우선 계산한다.

계산된 결과는 이력으로 남아 나중에 다시 찾아볼 수 있고, 계열사별 시스템 목록과 영향도(가중치) 값은 시간이 지나며 바뀔 수 있으므로 별도 화면에서 직접 관리할 수 있다.

우선 **유진기업** 계열사만 반영하고, 나머지 계열사(동양 / 유진홈센터 / 자산운용)는 이후 단계에서 추가한다.

## Features

1. **영향도-기준표-관리** — 계열사(우선 유진기업)의 시스템 목록과 각 항목별 영향도(가중치) 값을 화면에서 등록·수정한다. 장애등급 계산의 기준이 되는 데이터를 코드 수정 없이 최신 상태로 유지하기 위한 화면이다.
2. **장애등급-계산** — 계열사를 고르고, 장애가 발생한 시스템(중복 선택 가능)과 비즈니스영향도 / 장애복잡도(단순·복잡) / 고객서비스영향도(접속장애여부·응답속도·동일장애재발) 항목을 체크하면 점수를 자동 합산해 장애등급(1등급/2등급/3등급/등급외)을 즉시 보여준다. 모든 항목은 반드시 선택해야 계산할 수 있으며, 판단이 애매하거나 아직 확인되지 않은 항목은 비워두지 않고 "미확인"을 직접 선택해야 한다. 미확인으로 선택된 항목은 등급이 더 높게 나오는 쪽으로 계산한다.
3. **장애-이력** (화면명: "장애등급 판정 이력") — 지금까지 산정한 장애등급 결과를 목록으로 조회하고, 건별로 당시 입력했던 항목과 최종 등급을 다시 확인한다.
4. **과거-장애-이력** (화면명: "과거 장애 이력") — 그동안 엑셀로 관리해온 실제 과거 장애 이력(팀명, 장애유형, 관계사, 원인, 조치내역, 소요시간 등)을 조회한다. "장애-이력"과 달리 도구가 자동 산정한 결과가 아니라 수기로 기록해온 별도의 대장이며, 등록/수정 없이 조회만 지원한다.

## Scope & Priorities

- 핵심(Core) 3개 기능(영향도-기준표-관리, 장애등급-계산, 장애-이력)은 서로 의존 관계가 있어 아래 순서로 만드는 것을 권장한다.
  1. 영향도-기준표-관리 (계산의 기준 데이터가 먼저 있어야 함)
  2. 장애등급-계산 (기준 데이터를 사용해 실제 계산)
  3. 장애-이력 (계산 결과를 저장·조회)
- 과거-장애-이력은 위 3개와 데이터·의존 관계가 없는 별개 기능으로, 순서에 상관없이 독립적으로 만들 수 있다.
- 계열사는 **유진기업**만 우선 구현한다. 다른 계열사는 나중에 데이터만 추가하면 되도록, 계열사 구분을 데이터 구조에 반영해둔다.

## Out of Scope

- **장애 전파** (등급별 보고 대상에게 알리는 것, 모바일 팀즈 SMS 등) — 다음 프로젝트에서 다룬다.
- **장애보고서 작성 및 최종 등급 재산정** — 3등급 이상인 경우 장애보고서를 쓰며 등급을 다시 산정하는 절차는 이번 범위 밖이다. 이번 도구는 "최초 신속 산정"까지만 다룬다.
- **동양 / 유진홈센터 / 자산운용 계열사 반영** — 유진기업 구조가 자리잡은 뒤 다음 단계에서 추가한다.
- **로그인/권한 구분** — 품질관리자 1인이 사용하는 도구로 가정하고, 별도 사용자 구분이나 권한 관리는 두지 않는다.

## Further Notes

- 계열사별 영향도 기준(시스템 목록, 가중치)은 데이터로 관리하며, 화면 코드에 하드코딩하지 않는다. 이렇게 해야 "영향도-기준표-관리" 화면에서 값을 바꾸는 것이 실제 계산에 바로 반영되고, 나중에 다른 계열사를 추가하기도 쉽다.
- 용어는 도메인 스토리(`docs/domain-story.md`)에 정리된 표현을 그대로 따른다: 비즈니스 영향도, 장애 복잡도, 고객서비스 영향도, 장애등급, 등급외, 장애등급 산정표, 장애보고서.
